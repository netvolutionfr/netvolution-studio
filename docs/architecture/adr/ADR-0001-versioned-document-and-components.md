# ADR-0001 — Versioned document and components

**Status:** Accepted on 10/29/2026 · **Date:** 10/29/2026 · **Ref.:** 00 §5, VE-02, VE-03; study §3–4

## Context

The document is the source of truth (not the HTML). It must be serializable, validated at the boundaries, versioned, independent of React/Astro/CMS, and prepare the multi-page site (milestone 2) and the AI commands (milestone 3).

## Recommended decision

1. **Envelope** `{ schemaVersion: 1, kind: 'ns.page', id, title, breakpoints, rootId, nodes, assets }`.
2. **Flat table** `nodes: Record<NodeId, Node>` with `children: NodeId[]`; the parent is derived in memory.
3. **Node** `{ id, type, name?, props, style, children }`; `id` = `/^n[a-z0-9]{8,}$/` (stable, safe as a CSS class), generated by `crypto.getRandomValues`.
4. **Typed styles** on an allowlist, structured values; responsive `{ base, [breakpointId] }`, desktop-first inheritance towards the nearest wider breakpoint.
5. **Breakpoints are data** of the document (`{ id, label, maxWidth }`), with no limit on their number.
6. **Rich text** as `Inline[]` (bold, italic, link); no HTML. Links as a discriminated union (`kind: 'url'` in milestone 1).
7. **Media** referenced by `assetId`; no hosting path in the props.
8. **Versions**: global `schemaVersion` + a `version` per component definition. `loadDocument(json)`: future version → `unsupported-version` refusal; older version → pure sequential migrations; then Zod validation, then semantic validation (references, single parent, cycle, nesting allowed by the registry, valid props) → `Diagnostic { code, path, message, nodeId? }[]`.
9. **Zod schemas** as the single source of the TS types, of validation and (later) of the JSON Schema.

## Alternatives

- **Nested tree** (illustration in 00 §5): more readable, but id uniqueness and moves are less safe; every move copies subtrees. Kept as a *view* (`toTree()`) for diagnostics/AI.
- **Styles as free CSS strings**: flexible but injectable and not inspectable. Rejected.
- **HTML for rich text**: requires a sanitizer and brings rendering surprises. Rejected.
- **A `design.tokens` field from milestone 1**: YAGNI; adding a `{ token }` value later is backward compatible.

## Consequences

- Commands handle ids, never tree paths.
- Semantic validation depends on the registry: `loadDocument(json, registry)`.
- Unknown types: loading refused with a diagnostic (no "ghost" node) in milestone 1.

## Open points

- [O] Flat table vs nested tree (recommendation: flat).
- [O] Desktop-first (recommended, familiar from Tatsu) vs mobile-first.
- [Settled] Move from `ns.page` to `ns.site`: ADR-0007, v1 → v2 migration delivered in milestone 2 (slice 1).
- [O] `ns-<id>` class vs `data-ns-id` to identify nodes in the canvas.
