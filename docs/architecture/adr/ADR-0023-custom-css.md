# ADR-0023 — Custom CSS: project stylesheet and classes

**Status:** Accepted on 11/02/2026 · **Date:** 11/02/2026 · **Ref.:** CLAUDE §5, §6, §8 and §9, ADR-0002, ADR-0009, ADR-0010, ADR-0017, ADR-0018, `docs/history/research/essai-import-tatsu.md`

## Context

Today the Studio excludes any hand-written CSS (guide, appendix A: "excluded by design"). Every setting goes through the inspector, which guarantees three things:

- **security**: no free content reaches the preview or the export;
- **fidelity**: the canvas and the export render the same CSS, generated by `toCss`;
- **quality**: accessibility and responsive behavior, checked by the bench.

This rule has a cost for the designer of a project. On the trial Tatsu site, 6 elements rely on theme classes (`fold3d`, `rightbutt`, `upbutt`) and several effects have no equivalent in the Studio yet (parallax, 3D tilt, slow zoom). Each one-off need currently waits for a new setting or a new component.

The aim is to open a supervised door, reserved for the designer of the project, without giving up these three guarantees.

## Decision

1. **Two optional additions to the model**: no change of `schemaVersion`, since a document without them stays valid.
   - `site.customCss`: the project stylesheet, at most 64 KB.
   - `node.classes`: at most 8 classes per element, of the form `[a-z][a-z0-9-]{0,39}`. The `ns-` prefix is reserved for the Studio and refused.

2. **Custom classes are the only guaranteed hook.** The `ns-<id>` classes and the internal classes of components (`ns-carousel-track`…) are not a public API and can change. The editor warns when the stylesheet targets them, without refusing it.

3. **The stylesheet is parsed, never inserted as typed.** Parsing goes through a CSS parser declared as a direct dependency (lightningcss, already present through Vite; MPL-2.0 license, with no effect on exported sites, which do not embed it), on the server when saving and in the Studio while typing. It refuses:
   - `@import`, `@charset`, `@namespace`;
   - `url()` outside the media library. The only allowed references are `url("ns-asset:<id>")`, resolved like background images (ADR-0017) and counted in the media's usages (removal refused while it is used);
   - `@font-face`: fonts go through imported fonts (ADR-0018);
   - `expression()`, `-moz-binding`, `behavior` and anything that does not re-serialize identically.

   The published stylesheet is **the parser's output**, not the typed text. A `</style>` sequence or a booby-trapped comment therefore cannot get through. An invalid stylesheet is not saved: the error is reported to the line, and the document stays unchanged.

4. **Confinement by layer.** The stylesheet is emitted in `@layer ns-custom`, declared after the layer of the generated styles.
   - The priority order is predictable: custom CSS wins over the Studio's styles, whatever the order of the files.
   - `!important` remains possible, but the editor flags it.

   The canvas is already an iframe: the stylesheet cannot reach the editor's interface. Selection overlays stay out of the document's DOM (CLAUDE §6).

5. **Same rules in the canvas and at export.** The canvas and the preview inject the parsed stylesheet in the same layer. The export publishes it in `src/styles/custom.css`, imported after the page styles and described in the README. The site stays readable and reversible.

6. **Structured commands**: `setProjectCss` and `setNodeClasses`. They benefit from undo, the log and, later, the same rights and validations for the AI (CLAUDE §8). Typing in the code editor is one transaction, closed when leaving the field.

7. **Interface.**
   - A **Project CSS** panel: monospaced code area (a text area at first), errors and warnings per line, live preview in the canvas.
   - A **CSS classes** field in the Advanced section of the inspector.

8. **Quality warnings, non-blocking**:
   - `outline: none` or `outline: 0` without a `:focus-visible` rule;
   - `display: none` or `visibility: hidden` outside a media query;
   - animations or transitions without `prefers-reduced-motion` in the stylesheet;
   - selectors targeting `ns-` classes;
   - `!important`.

   The accessibility bench (axe) remains the reference check.

9. **Rights.** As long as the Studio has no roles, the whole logged-in team can edit the stylesheet; acceptable on a private instance (ADR-0016). When roles arrive, it will be a permission of the designer, logged. A future client who edits content will not have it.

## Rejected alternatives

- **Free CSS without parsing**: injection possible in the preview and the export, third-party resources loaded unknowingly (Schrems II), no fidelity guarantee.
- **CSS specific to each element, scoped automatically to the element**: useful, but scatters style over hundreds of nodes, hard to review and maintain. The project stylesheet and the classes cover the observed needs; to reconsider on a real need.
- **Predefined utility classes and CSS variables only**: safer, but does not meet a designer's need (effects, selectors, states).
- **Sanitizing with regular expressions**: can be bypassed; only a re-serializing parser gives a guarantee.

## Consequences

- The principle "no custom CSS" becomes "no uncontrolled custom CSS". The guide (appendix A and a new chapter or section) and `docs/limitations.md` are updated.
- Fidelity bench: a fixture with a custom stylesheet (classes, `@media`, `url("ns-asset:…")`, `:hover` state). Refusal tests: `@import`, external `url()`, `@font-face`, `</style>`, `ns-` prefix in classes.
- The Tatsu converter could carry the theme classes (`fold3d`…) over to the elements; the matching stylesheet remains for the designer to write, without copying Oshine's CSS.
- Accepted risk: a custom stylesheet can degrade the accessibility or responsive behavior of a site. The warnings and the bench report it, they do not prevent it.
- Debt: the internal classes of components may evolve; a stylesheet that targets them despite the warning may break with an update.
- One more direct dependency (the CSS parser), whose license and patches must be followed (CLAUDE §8).

## Addendum of 11/02/2026 — implementation

- **Parser: css-tree (MIT, 3.2.1) instead of lightningcss.** lightningcss is a native module: it does not run in the browser, where the Studio validates every document (canvas, preview). css-tree is pure JavaScript and serves everywhere: Studio, server (`loadSite`) and export. The guarantee is the same: the published stylesheet is the output of `generate()`, never the typed text. Also refused: escapes in names (`\75rl(`), functions that load a resource from a string (`src()`, `image()`, `image-set()`, `cross-fade()`), the `<` character in a string, and any unrecognized syntax. Custom properties (`--x`) are parsed as values, hence checked as well.
- **Layers.** A stylesheet in a layer loses against styles outside any layer. The generated styles (`toCss`) therefore go in the `ns` layer, declared before `ns-custom` (`@layer ns,ns-custom;`). The canvas and the preview have no other stylesheet; section thumbnails are rendered in a shadow DOM, without the project stylesheet.
- **Media.** `url("ns-asset:<id>")` is resolved to `/media/<file>` (served as is, like background images); the media library refuses to remove an image used by the stylesheet. The panel offers to insert an image from the media library.
- The `setProjectCss` and `setNodeClasses` commands require the `design` permission, granted to the AI assistant: its proposals go through the same validation and the human review of the differences.
- The Tatsu converter carried the section and column classes of the theme (`fold3d`…) over to the elements.
- **Syntax highlighting** without an extra dependency: css-tree's tokenizer colors a copy (`<pre aria-hidden>`) placed under a `<textarea>` with transparent text, which remains the real control (keyboard, screen readers, browser undo). The e2e test checks that the two line up.
- **Export without CSS minification** (`vite.build.cssMinify: false`). The minifier rewrote some values (`right top` to `100% 0`, `background: transparent` to `background: 0 0`): same rendering, but computed values different from the Studio's, which the fidelity bench detected. The generated CSS is already compact; the project stylesheet keeps its line breaks.
